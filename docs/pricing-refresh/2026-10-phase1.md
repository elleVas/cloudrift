# Pricing refresh — 2026-10 (phase 1/3: storage)

Date: 2026-10-01

Scope: storage-related price keys only (`ebs-gp2`, `ebs-gp3`, `ebs-io1`, `ebs-io2`,
`ebs-st1`, `ebs-sc1`, `ebs-standard`, `ebs-snapshot`, `s3-standard`, `efs-standard`,
`cw-logs`, `ecr-storage`, `rds-manual-snapshot`) in
`libs/shared/cloud-cost-pricing/src/prices.json` (the file now lives there per
ADR-0098; `libs/cloud-cost/infrastructure/aws-adapter/src/pricing/` just re-exports
it). Network/FSx and database/app-services keys are covered by separate phase 2/3
routines and were not touched here.

The `aws.amazon.com` marketing pricing pages are blocked by this session's egress
policy, so prices were verified against AWS's official Price List Query API
(`pricing.us-east-1.amazonaws.com`), the same machine-readable feed that backs
those pages. For EBS, S3, EFS and CloudWatch Logs, prices were pulled for all six
regions in the table (`us-east-1`, `us-west-2`, `eu-west-1`, `eu-central-1`,
`ap-southeast-1`, `ap-northeast-1`); for ECR and RDS manual snapshots, only
`us-east-1` was needed since those keys exist solely in the `default` table.
Source file publication dates: AmazonEC2 (EBS) 2026-09-25, AmazonS3 2026-09-28,
AmazonEFS 2026-09-11, AmazonCloudWatch 2026-09-22, AmazonECR 2026-09-11, AmazonRDS
2026-09-29 — all within the last three weeks of this run.

## Known test fallout

`libs/shared/cloud-cost-pricing/src/static-price-table.adapter.spec.ts:40` asserts
`adapter.getPrice(apSoutheast1, 'ebs-snapshot')` equals the old value `0.055`. This
test will now fail against the corrected `0.050` value. Per this run's scope (only
`prices.json` and this log file), the spec file was intentionally left unmodified;
it needs a one-line update (`0.055` → `0.05`, and the test's "higher than
us-east-1" comment/description no longer holds since the two are now equal) as
part of landing this PR.
