# Pricing refresh — 2026-10 (Phase 2/3: network & FSx)

Date: 2026-10-01

Scope: `elastic-ip`, `load-balancer`, `nat-gateway`, `vpn-connection`,
`transit-gateway-attachment`, `kinesis-shard`, `fsx-windows`, `fsx-lustre`,
`fsx-ontap`, `fsx-openzfs` in `prices.json` (currently at
`libs/shared/cloud-cost-pricing/src/prices.json` — the file at the path
named in this phase's instructions,
`libs/cloud-cost/infrastructure/aws-adapter/src/pricing/prices.json`, is now
a re-export shim per ADR-0098 that points at this location; confirmed by
reading `static-price-table.adapter.ts`, which imports `prices.json` from
the same directory and is the file that `StaticPriceTableAdapter` actually
loads at runtime).

Sourcing note: `aws.amazon.com` (and `docs.aws.amazon.com`) are blocked by
this environment's network egress policy, same as in the 2026-07 run, so the
marketing/doc pricing pages named in this phase's instructions could not be
fetched directly. This time, `pricing.us-east-1.amazonaws.com` — AWS's
official machine-readable Price List Bulk API — was reachable through the
proxy. Its per-region, per-service JSON files are the same list-price data
that backs the aws.amazon.com pricing pages, published directly by AWS, and
the fetched files carried `publicationDate: 2026-09-25`, i.e. current at the
time of this run. All prices below were read directly from that API's
`priceDimensions[*].pricePerUnit.USD` fields for the relevant SKUs (NAT
Gateway: `AmazonEC2`, usagetype `NatGateway-Hours`; Elastic IP/Public IPv4:
`AmazonVPC`, usagetype `PublicIPv4:InUseAddress`; Transit Gateway
attachment and VPN connection: `AmazonVPC`, usagetype
`TransitGateway-Hours` / `VPN-Usage-Hours:ipsec.1`; Kinesis:
`AmazonKinesis`, usagetype `Storage-ShardHour`; ELB: `AWSELB`, usagetype
`LoadBalancerUsage` for the `Load Balancer-Application` family; FSx:
`AmazonFSx`, `productFamily: Storage`, Single-AZ SSD deployment per
filesystem type) — no WebSearch/aggregator-site numbers were used. Hourly
rates were converted to the file's monthly convention using the same
per-key factor the existing data already implies (730 h/mo for
`vpn-connection`/`transit-gateway-attachment`/`kinesis-shard`, 720 h/mo for
`elastic-ip`/`load-balancer`/`nat-gateway`; FSx keys are already
$/GB-month, no conversion needed).

The `default` table's existing values for these keys matched the US East
(N. Virginia) rates from the API almost exactly (see "unchanged" list
below), confirming `default` == us-east-1 pricing, consistent with the
other keys already in the file.
